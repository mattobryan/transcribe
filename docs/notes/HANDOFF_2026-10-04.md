## Transcript Corrector (main deliverable of the last days)

- Live artifact (private): https://claude.ai/artifact/BbFwzTDPRpGMG9cKXDUKsz (version 14, capability `downloads`).
- Source in repo: `tools/corrector/` (`index.html` built; `src/{head,style,body,script}.part`; `build.py`; `lexicon.py`;
  `smoke_test.py`; README). Edit `src/`, run `python build.py`, then publish `index.html` with the Artifact tool
  (`url` = the link above, after reading it; `capabilities` are carried forward). Single file, no server, nothing uploaded.
- It loads the Scribe JSON + the recording (audio only, hidden `<video>`), chunks by speaker/pause, and shows the whole
  interview as one script (left) with the editor, transport and format buttons pinned (right), plus a vertical timeline rail
  with playhead and checked/flagged marks.
- Behaviour decided with the user (keep these):
  - Lines `I:` (interviewer, **bold**, whole line) and `R:` (respondent, plain); `I2:`/`R2:` allowed. First speaker = interviewer
    (changeable under Speakers). Enter starts a line for the other speaker (setting; Shift+Enter keeps speaker).
  - Cleaning: remove a speaker's own fillers (um, uh, ah, mm-hmm ...); the other speaker's backchannel is kept only at the
    **end of a sentence**, dropped if it interrupts a sentence that the same speaker finishes. Dash/ellipsis convention:
    `--` self-correction, one `-` cut off by the other speaker, `...` the speaker's own pause. When only a backchannel
    interrupted, the dash and the ellipsis are removed. Capital letters when pieces join (capital after a finished sentence,
    lower case after an unfinished one; names and "I" untouched). Comma after a sentence-opening "So" when a clause follows
    (assumption: this is what "a comma after a plain so" meant; ask if wrong). Typed first letter of a line/sentence is capitalised.
  - Swahili is italicised automatically (word list from this interview + English top-30k list + verb-prefix rules;
    `ku`, `tuna`, `ana` + English stem handled). User marks override: `**bold**`, `_italic_` (Swahili), `~plain~` (not Swahili);
    marks may touch letters so one word can be part Swahili/part English: `_ni_break_ie_`. B / I / Not Swahili / Clear buttons.
  - Audio: typing **pauses** the audio; while there are unsaved edits the audio stays inside the chunk. **Save, play next
    chunk** (Ctrl+Enter) plays the next chunk and stops at its end; **Save and continue** (Ctrl+Shift+Enter) keeps playing the
    whole script. Esc play/pause, F1/F2 -/+3 s, F3/F4 speed, Alt+E edit what I'm hearing, Alt+N next flagged, Alt+I switch I:/R:.
    Buttons never take focus from the editor (keeps the tablet keyboard up).
  - Export: file name box; with/without timestamps; **Word .docx** (Times New Roman 12 pt everywhere, one blank line after
    each paragraph, header = file name, bold capital title, "I: Interviewer" bold / "R: Respondent", script with bold+italic,
    footer "Page x of y"); copy formatted / plain / SRT / JSON; **corrections log (.json)** and **word changes (.csv)**.
  - Flags: red `!` on chunks with low-confidence words, "resumes after a cut-off", "short continuation after a cut-off: check
    who says it" (11 chunks), and a user list of words to review (Flags button; default 15 words: ukfeel, wanakoconsult,
    tunabidi, tutamisse, zinezinamotivate, mnitaita, nitad, nyali, rusa, asongee, soile, wueh, locummers, aeration, mem).
- Not verified on the real device: on-screen keyboard behaviour after Play, long-press text selection with the format buttons,
  finger drag on the rail, how Word/Google Docs render the .docx (LibreOffice in the sandbox cannot open any .docx, so only

- Tests: `TRANSCRIPT=... CHROMIUM=... JSZIP=... python tools/corrector/smoke_test.py` (12 checks, all passing at hand-off).

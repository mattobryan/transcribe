\section{Architecture overview}\label{architecture-overview}}

\begin{figure}[!htbp]\centering
\resizebox{\ifdim\width>\linewidth\linewidth\else\width\fi}{!}{\input{figures/architecture}}
\caption{System architecture: local CPU services and Kaggle GPU training.}
\end{figure}

Principles:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \textbf{Human text is authoritative.} Model output is stored as a \emph{hypothesis} next to reviewer text and is never written over it.
\item
  \textbf{Immutability.} Source audio and transcripts are content-addressed (sha256) and never modified. Datasets are frozen snapshots, and model versions point to exactly one snapshot.
\item
  \textbf{One process model.} A single user on CPU needs no Redis or Celery. A worker process polls a jobs table in SQLite.
\item
  \textbf{Engines behind interfaces.} Aligner, VAD and ASR are swappable: a Protocol plus a registry, so the CTC comparison model or a larger Whisper plugs in without UI changes.
\end{enumerate}

\hypertarget{model-strategy}{%
\section{Model strategy}\label{model-strategy}}

\hypertarget{why-not-a-proper-english-model--a-proper-swahili-model-blended}{%
\subsection{Why not ``a proper English model + a proper Swahili model, blended''}\label{why-not-a-proper-english-model--a-proper-swahili-model-blended}}

This was the proposal in the requirements discussion. It does not work for Kenyan code-switching, for three reasons:

\begin{itemize}
\tightlist
\item
  \textbf{Routing needs per-word language ID before transcription.} A router (language ID → English or Swahili model) decides per segment. Switches happen mid-sentence and \emph{mid-word} (\emph{nimedownload}), below any practical language-ID granularity. Every routing error becomes a transcription error.
\item
  \textbf{Monolingual models cannot output the other language.} A Swahili model spells English words in Swahili orthography (\emph{daunlodi}), and an English model maps Swahili words onto English lookalikes. Merging hypotheses (ROVER-style) needs both hypotheses to contain the right word somewhere, and for intra-word switches neither does.
\item
  \textbf{Cost and complexity.} It needs twice the compute on CPU, two fine-tuning tracks, and a merge heuristic with no training signal.
\end{itemize}

\textbf{What we do instead:} one multilingual pretrained model whose pretraining already covered both languages, fine-tuned on Kenyan code-switched speech. The blending happens in two places where it works:

\begin{itemize}
\tightlist
\item
  \textbf{The data mixture.} In-domain code-switched segments, plus public Kiswahili and public Kenyan-accented English, blended by sampling weights. This teaches the switch and keeps both monolingual abilities.
\item
  \textbf{The tokenizer.} Whisper\textquotesingle s byte-level BPE can emit any Latin string, so \emph{nime} + \emph{download} is just a token sequence. Nothing forces a single language per word.
\end{itemize}

\hypertarget{whisper-fine-tuning-specifics}{%
\subsection{Whisper fine-tuning specifics}\label{whisper-fine-tuning-specifics}}

\begin{itemize}
\tightlist
\item
  \textbf{Language token:} fixed \texttt{<|\allowbreak{}sw|\allowbreak{}>} + \texttt{<|\allowbreak{}transcribe|\allowbreak{}>} + \texttt{<|\allowbreak{}notimestamps|\allowbreak{}>} for all training samples. Kenyan code-switching is predominantly Kiswahili-framed, and a fixed token removes the language-ID step at inference. \textbf{Experiment E3} compares \texttt{sw} vs \texttt{en} vs no language token on the dev set. This is a cheap and instructive ablation.
\item
  \textbf{Non-speech examples:} about 5\% of training samples are music/noise/silence windows with an empty target. This is the most direct fix for church and TV hallucination.
\item
  \textbf{Data mixture (v1):} in-domain approved segments weight 1.0. Public Kiswahili (Common Voice sw, FLEURS sw\_ke) weight about 0.3, to prevent forgetting and add speaker diversity. Kenyan-accented English (AfriSpeech-200 Kenyan subset) weight about 0.2. Licences must be checked before any commercial use (AfriSpeech is non-commercial).
\item
  \textbf{Hyperparameters (starting point, T4 16 GB):} fp16, lr 1e-5, warmup 500, per-device batch 16 with gradient checkpointing, effective batch 32, 3--5k steps, evaluate every 500 steps on dev WER, keep the best checkpoint. SpecAugment is on (\texttt{mask\_\allowbreak{}time\_\allowbreak{}prob=\allowbreak{}0.\allowbreak{}05}).
\item
  \textbf{Kaggle constraints:} a weekly GPU quota (\textasciitilde30 h) and a hard per-session limit, so we save checkpoints to \texttt{/\allowbreak{}kaggle/\allowbreak{}working} every 500 steps, the training script supports \texttt{resume\_\allowbreak{}from\_\allowbreak{}checkpoint}, and one session does one experiment.
\end{itemize}

\hypertarget{why-the-legacy-model-cannot-be-the-product}{%
\subsection{Why the legacy model cannot be the product}\label{why-the-legacy-model-cannot-be-the-product}}

\begin{itemize}
\tightlist
\item
  Hop 512 at 16 kHz gives 32 ms frames, and the three pooling layers make that 256 ms per CTC output frame. A 30 s segment has about 117 frames against about 400 target characters, and CTC requires frames ≥ target length. \texttt{CTCLoss(zero\_\allowbreak{}infinity=\allowbreak{}True)} silently zeroes these losses.
\item
  The tokenizer removes spaces, so output cannot be readable.
\item
  It has no pretraining, and hundreds of hours of audio are needed before from-scratch ASR becomes competitive with a fine-tuned pretrained model.
\end{itemize}

If kept for learning, fix it with hop 160 (10 ms), 2× downsampling, a space token, and no SOS/EOS in CTC targets.

\hypertarget{corpus-pipeline}{%
\section{Corpus pipeline}\label{corpus-pipeline}}

\begin{lstlisting}
ingest → normalise audio → parse transcript → normalise text for alignment
→ long-form alignment → word timestamps + scores → segmentation
→ auto-flags + priority score → review → approve → dataset snapshot
\end{lstlisting}

\hypertarget{ingest}{%
\subsection{Ingest}\label{ingest}}

\begin{itemize}
\tightlist
\item
  ffmpeg decodes to a 16 kHz mono 16-bit WAV. The original file is kept byte-identical, stored at \texttt{data/\allowbreak{}store/\allowbreak{}originals/\allowbreak{}<sha256>.\allowbreak{}<ext>}.
\item
  The transcript is parsed by the existing \texttt{docx\_\allowbreak{}parser} / \texttt{pdf\_\allowbreak{}parser}. The speaker regex and language hints (italic → \texttt{sw}, a convention that is verified per source) are reused.
\end{itemize}

\hypertarget{text-normalisation-for-alignment-a-separate-text-never-shown-as-the-label}{%
\subsection{Text normalisation for alignment (a separate text, never shown as the label)}\label{text-normalisation-for-alignment-a-separate-text-never-shown-as-the-label}}

\begin{itemize}
\tightlist
\item
  Remove bracketed annotations (\texttt{[unclear]}, \texttt{[laughs]}, \texttt{[crosstalk]}), but record their word positions for flags.
\item
  Lowercase, and romanise with uroman (a no-op for Latin script, but it normalises diacritics and apostrophes).
\item
  Numbers are verbalised (\href{STYLE_GUIDE.pdf}{STYLE\_GUIDE §4}). For each digit token the pipeline generates an English and a Kiswahili candidate (the default comes from the span language, years → English, labels → English title case). It aligns both candidates locally and keeps the one with the higher score. If the scores differ by less than a margin (initially 0.1), the word becomes the \texttt{*} wildcard and the segment is flagged \texttt{number\_\allowbreak{}check}. The chosen spoken form becomes the segment label. English uses \texttt{num2words}; Kiswahili uses a small rule-based verbaliser in \texttt{corpus/\allowbreak{}numbers\_\allowbreak{}sw.\allowbreak{}py} (the system is regular, and it gets unit tests from the style guide table).
\item
  Optional display ITN (words → digits) runs on Transcribe output only (P1), never on training text.
\item
  Keep a word-level index map \texttt{norm\_\allowbreak{}word\_\allowbreak{}i → source\_\allowbreak{}char\_\allowbreak{}span} so aligned timestamps map back onto the \textbf{original} transcript text, which becomes the segment label.
\end{itemize}

\hypertarget{long-form-alignment}{%
\subsection{Long-form alignment}\label{long-form-alignment}}

\begin{itemize}
\tightlist
\item
  CTC emissions are computed over the full audio in 30 s windows with 2 s overlap, then stitched.
\item
  Alignment is turn-anchored: each transcript turn is aligned inside a search window around its expected position (moving anchor). This keeps the Viterbi trellis small (T × L per turn instead of per recording) and localises damage from non-verbatim passages.
\item
  Output per word: \texttt{start\_\allowbreak{}s}, \texttt{end\_\allowbreak{}s}, and \texttt{score} (mean frame log-posterior, turned into a 0--1 confidence).
\item
  A turn whose mean confidence is below θ (initially 0.5, tuned on the first reviewed recording) is flagged \texttt{low\_\allowbreak{}alignment}. That is the usual signature of a non-verbatim or missing passage.
\end{itemize}

\hypertarget{priority-score-for-the-review-queue}{%
\subsection{Priority score for the review queue}\label{priority-score-for-the-review-queue}}

\begin{lstlisting}
priority = 0.5·(1 − alignment_conf) + 0.2·has_unclear_marker + 0.1·overlap_marker
         + 0.2·model_disagreement (WER(aligned_text, model_hypothesis), once a model exists)
\end{lstlisting}

The review queue sorts by \texttt{priority} descending. Segments with high confidence and low disagreement can be \textbf{batch-approved after spot-checking} a random 10\%, controlled by a setting and off by default.

\hypertarget{recordings-without-transcripts}{%
\subsection{Recordings without transcripts}\label{recordings-without-transcripts}}

Silero VAD splits them into ≤ 30 s chunks, the current production model pre-fills the text (stored as a hypothesis, with the reviewer text starting from a copy), and they go into the same review UI.

\hypertarget{inference-pipeline}{%
\section{Inference pipeline}\label{inference-pipeline}}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Decode with ffmpeg → 16 kHz mono float32.
\item
  Silero VAD (threshold 0.5, min speech 250 ms, min silence 400 ms) gives speech regions.
\item
  Merge regions into windows of ≤ 30 s.
\item
  Run faster-whisper on each window: \texttt{language=\allowbreak{}"sw"}, \texttt{task=\allowbreak{}"transcribe"}, \texttt{beam\_\allowbreak{}size=\allowbreak{}5}, \texttt{condition\_\allowbreak{}on\_\allowbreak{}previous\_\allowbreak{}text=\allowbreak{}False}, \texttt{word\_\allowbreak{}timestamps=\allowbreak{}True}, \texttt{vad\_\allowbreak{}filter=\allowbreak{}False} (VAD has already been applied).
\item
  Guards: drop segments with \texttt{no\_\allowbreak{}speech\_\allowbreak{}prob > 0.\allowbreak{}6} and \texttt{avg\_\allowbreak{}logprob < −1.\allowbreak{}0}. Drop segments with compression ratio \textgreater{} 2.4 (repetition loops). Collapse a 3-gram repeated more than 3 times.
\item
  Post-processing: timestamps are offset back to absolute time, and segments are persisted as \texttt{job\_\allowbreak{}segments}.
\item
  Export renderers: TXT, SRT, VTT, JSON, DOCX.
\end{enumerate}

Batching: windows run sequentially, with \texttt{cpu\_\allowbreak{}threads =\allowbreak{} physical cores} and \texttt{compute\_\allowbreak{}type=\allowbreak{}"int8"}. Progress = processed audio seconds / total speech seconds.

\hypertarget{evaluation}{%
\section{Evaluation}\label{evaluation}}

\hypertarget{splits-answers-how-should-we-split}{%
\subsection{Splits (answers ``how should we split?'')}\label{splits-answers-how-should-we-split}}

\begin{itemize}
\tightlist
\item
  \textbf{Group by recording, never by chunk.} Chunks from one recording share speaker, microphone, room and topic, so a random chunk split leaks all of them and inflates results.
\item
  If a speaker appears in several recordings (the same interviewer), group by speaker cluster: all recordings of that speaker go to the same split, or that speaker is held out explicitly.
\item
  \textbf{Size dev/test in hours and recordings, not percentages.} Evaluation sets only need to be big enough for a stable WER, and variance comes from speakers and recordings more than from word count. Long-run target: \textbf{test ≈ 3 h from ≥ 15 recordings, dev ≈ 2--3 h from ≥ 10 recordings}. Everything else is train; as audio keeps arriving, train grows and dev/test stay fixed.
\item
  \textbf{Current corpus (v1): 11 recordings, 8 h 56 min.} test\_v1 = 2 recordings (≈ 1.5 h, 17\%), dev\_v1 = 1 recording (≈ 50 min, 10\%), train = 8 recordings (≈ 6.5 h, 73\%), including the 2 h 05 min recording. The test set is larger than dev because it is the number every model version is judged on; dev only has to rank checkpoints. With so few recordings a single test pair is noisy, so final v1 numbers are also reported as leave-two-recordings-out cross-validation over 3 folds (3 Kaggle runs), and the frozen split is kept for version-to-version comparison.
\item
  \textbf{Shared speakers:} if one interviewer appears in every recording, their speech is in every split. Reports then include a \emph{respondent-only} WER, which is the honest measure of generalisation to new speakers.
\item
  \textbf{Test is frozen forever} (for comparability across model versions), stratified so it contains clean and noisy, low and high code-switch density, and each domain available. Dev is used for checkpoint selection and ablations.
\item
  \textbf{Audio still arriving:} fix \texttt{test\_\allowbreak{}v1} and \texttt{dev\_\allowbreak{}v1} from the recordings available at the end of Phase 2, and never change them. New recordings go to train by default. A new domain or a clearly new condition (TV, church, a new region) first contributes ≈ 1 h to an \texttt{external\_\allowbreak{}<domain>} test set.
\item
  New recordings go to train by default. New \emph{domains} (TV, church) first get a held-out evaluation set of ≥ 1 h before any of their data goes into train.
\item
  Also keep FLEURS \texttt{sw\_\allowbreak{}ke} test as a forgetting check. Test-set segments are never used for anything except final reports.
\end{itemize}

\hypertarget{normaliser-versioned-normalizer_version-stored-with-each-evaluation}{%
\subsection{\texorpdfstring{Normaliser (versioned, \texttt{normalizer\_version} stored with each evaluation)}{Normaliser (versioned, normalizer\_version stored with each evaluation)}}\label{normaliser-versioned-normalizer_version-stored-with-each-evaluation}}

Lowercase. Strip punctuation except intra-word apostrophes. Remove hyphens (so \emph{nime-download} ≡ \emph{nimedownload}). Collapse whitespace. Remove bracketed annotations. Map a small table of spelling variants (e.g. \emph{ok/okay}) from the style guide. Verbalise any remaining digits with the same rules as the corpus pipeline, so digit and word outputs score the same.

\hypertarget{security-and-privacy}{%
\section{Security and privacy}\label{security-and-privacy}}

\begin{itemize}
\tightlist
\item
  The app binds to \texttt{127.\allowbreak{}0.\allowbreak{}0.\allowbreak{}1} by default. Exposing it on a network requires setting \texttt{TRANSCRIBE\_\allowbreak{}AUTH\_\allowbreak{}TOKEN} (a bearer token middleware) in v1.
\item
  \texttt{consent\_\allowbreak{}scope ∈ \{training,\allowbreak{} eval\_\allowbreak{}only,\allowbreak{} transcription\_\allowbreak{}only\}} on every recording is enforced in the dataset builder (training split only from \texttt{training}), in the Kaggle export, and in ``promote to corpus''.
\item
  Kaggle datasets are created private. The export package contains only audio slices and text, never names from the transcript header or file paths.
\item
  No demographic or ethnicity fields are stored. Speaker labels are opaque (\texttt{S1}, \texttt{interviewer}).
\item
  Uploaded transcription files are deleted after N days (configurable) unless promoted.
\end{itemize}
